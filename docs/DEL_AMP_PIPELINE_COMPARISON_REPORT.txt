CRESCENT: AMP AND DEL PIPELINE COMPARISON
=========================================

Scope
-----

This report describes the amplification (amp) and deletion (del) branches in
the CRESCENT-dev pipeline. Both branches feed the same dataset class, model, and
leave-one-project-out training script:

  Model/auto_cross_ct_val.py


1. SHARED END-TO-END PIPELINE
-----------------------------

  Data/merged_dataframe/merged_dataframe_<CANCER>.tsv
      -> mutation-specific chromosome matrices
      -> 40-column patient-axis compression
      -> mutation-specific center labels
      -> three-scale labeled TSV samples
      -> Model/utils/Dataset.py
      -> Model/Models.py
      -> Model/utils/train.py and Model/utils/evaluate.py
      -> Model/auto_cross_ct_val.py
      -> leave-one-project-out results in experimental/<mutation>/


2. MUTATION-SPECIFIC FILES
--------------------------

Stage                    amp                              del
-----------------------  -------------------------------  -------------------------------

                         gen_bin_0306_cpp.cpp

                         with mut="amp"                   with mut="del"

Sample generator         gen_sample_amp.py                gen_sample_del.py

3. MATRIX REPRESENTATION
------------------------

amp
  preprocess/Version0209/sort.py identifies arm-level segments using the GRCh38
  chromosome-arm reference and writes per-chromosome segment files.

  preprocess/Version0209/gen_bin_0306_cpp.cpp removes arm-level records, creates
  bins from the remaining segment endpoints, and writes raw covering copy-number
  values. Uncovered sample bins are represented by diploid value 2.

del
  preprocess/Version0209/gen_bin_del.cpp uses only records with Copy_Number < 2
  to define bin boundaries. Every sample/bin begins at 2. A deletion covering a
  complete bin subtracts 2 - Copy_Number. Copy gains do not contribute to the
  deletion matrix.

The two representations are therefore not sign-flipped copies. They use
different bin grids and different numerical signals, so their center indices and
checkpoints are not interchangeable.


4. PATIENT-AXIS COMPRESSION
---------------------------

preprocess/compress.py standardizes matrices to 40 patient columns:

  1. Separate the first three metadata columns and final suffix column.
  2. If fewer than 40 patient columns exist, pad with diploid value 2.
  3. Rank patient columns by whole-matrix mean.
  4. Keep the 40 highest-mean columns as anchors.
  5. Assign remaining columns round-robin to the anchors and average each group.

Set mut="amp" or mut="del" near the top of the script before running it.


5. LABELS AND SAMPLE GENERATION
-------------------------------

amp uses:

  gen_dataset/config.yaml
  gen_dataset/type_centers_index.yaml
  gen_dataset/gen_sample_amp.py

del uses:

  gen_dataset/config_del.yaml
  gen_dataset/type_centers_del.yaml
  gen_dataset/gen_sample_del.py

Both label manifests organize centers as:

  TYPE_CENTERS
    <cancer project>
      <chromosome>
        pos: [row indices]
        neg: [row indices]

Both generators:

  * resolve positive centers to label 1 and negative centers to label 0;
  * extract three centered genomic windows;
  * sort patient columns by descending mean;
  * pad or fold columns to the configured width;
  * write one TSV per labeled center.

The main generator difference is the three configured window heights. Amp uses
broader genomic contexts; del uses smaller contexts around deletion signals.


6. SHARED DATASET AND MODEL
---------------------------

Model/utils/Dataset.py parses the label and all scale blocks from each generated
TSV. The mutation name does not change parsing.

Model/Models.py defines ComplexMultiStreamCNN. It applies the same branch design
to every scale, combines scale features with multi-head attention, averages the
refined branch vectors, and produces one binary logit.

The model contains no amp-versus-del conditional computation. Mutation type is
determined before training by the selected matrices, labels, scale shapes,
sample directory, and output namespace.


7. SHARED TRAINING AND VALIDATION
---------------------------------

Model/auto_cross_ct_val.py is the training and validation script for both
mutation types. For each requested cancer project it:

  1. holds out that project's samples as validation data;
  2. trains on all other projects;
  3. uses BCEWithLogitsLoss and Adam;
  4. schedules learning rate from validation loss;
  5. evaluates train and validation metrics each epoch;
  6. selects the checkpoint with the highest validation F1, using AUC as the
     tie-breaker;
  7. writes metrics, checkpoints, ROC data, plots, timings, and a project-level
     summary.

Before running, configure mut_type, data_dir, cancer_list, seeds, and training
hyperparameters in Model/auto_cross_ct_val.py. Amp and del must use separate
generated-sample directories and result namespaces.


8. PRACTICAL FILE ORDER
-----------------------

Read or run the canonical pipeline in this order:

  1. Data/merged_dataframe/
  2. preprocess/Version0209/sort.py and gen_bin_0306_cpp.cpp for amp,
     or preprocess/Version0209/gen_bin_del.cpp for del
  3. preprocess/compress.py
  4. gen_dataset/config.yaml or config_del.yaml
  5. gen_dataset/type_centers_index.yaml or type_centers_del.yaml
  6. gen_dataset/gen_sample_amp.py or gen_sample_del.py
  7. Model/utils/Dataset.py
  8. Model/Models.py
  9. Model/utils/train.py and Model/utils/evaluate.py
 10. Model/auto_cross_ct_val.py


9. OTHER DEVELOPMENT VERSIONS
------------------------------

The original source tree also contained experimental files that are not part of
the canonical CRESCENT-dev pipeline:

  * auto_cross_ct_val_03.py: earlier 50-epoch leave-one-project-out settings.
  * auto_cross_ct_val_before0913.py and auto_cross_ct_val_baseline.py: older
    AUC-oriented checkpoint selection.
  * auto_cross_ct_val_shin0905.py with Dataset_neo0905.py: balanced domain/label
    batch sampling.
  * theta.py and kFold_panCancer.py: ordinary stratified k-fold experiments,
    not leave-one-project-out validation.
  * gen_sample_del_old.py: historical deletion scales of 50/100/500.
  * dated type_centers_index files: historical label snapshots consolidated
    into the two manifests retained by this archive.
  * center_position.yaml with centers_coord_to_index.py: coordinate-based label
    conversion retained for provenance.
  * rubic_sim_a.yaml: auxiliary RUBIC simulation labels.

These names are useful only for interpreting old results. New development runs
use the pipeline in Sections 1-8 and Model/auto_cross_ct_val.py.
