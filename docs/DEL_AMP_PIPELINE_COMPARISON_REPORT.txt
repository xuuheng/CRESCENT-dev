CRESCENT PROJECT: SYSTEMATIC COMPARISON OF THE "del" AND "amp" PIPELINES
===============================================================================

Report date: 2026-09-15
Scope: read-only analysis of this repository plus the Materials and Methods of
"CRESCENT: a deep learning framework with multi-scale attention for detecting
recurrent copy number alterations." No source code was changed and this is not
intended as a bug audit.

Primary article source:
https://pmc.ncbi.nlm.nih.gov/articles/PMC13089434/
Direct paper copy:
https://fengslab.com/data/crescent.pdf


1. EXECUTIVE SUMMARY
--------------------

The two pipelines are separate mainly BEFORE training, when chromosome matrices
and labeled multi-scale samples are constructed. Once samples have been written,
both mutation types use the same dataset parser, the same multi-branch CNN and
attention architecture, the same binary loss, and essentially the same training
logic. In the training functions, the `mut` value mostly selects the input/output
directory; it does not change the model computation.

The central biological/data distinction is:

* amp preserves the ordinary copy-number landscape in its matrix (after removal
  of arm-level records in the focal preprocessing path inspected here). Values
  above 2 remain high amplification signal, but values at or below 2 can also be
  present.
* del constructs a deletion-only landscape. Only records with Copy_Number < 2
  define bins and update values. Each sample starts from diploid value 2 and is
  reduced by 2 - Copy_Number. Amplification records are therefore excluded from
  the deletion representation.

The article explicitly explains the deletion transformation: copy-number values
greater than 2 are ignored and the remaining values are represented relative to
the diploid state. This prevents relatively sparse deletion patterns from being
masked by the wider numeric range of amplifications.

The intended multi-scale windows also differ because the empirical CNA-length
distributions differ:

  Article amp: 50x40, 100x40, 2000x40
  Article del: 20x40,  50x40,  400x40

The checked-in current YAML agrees exactly for del, but the current amp YAML has
50x40, 250x40, 2000x40. Older/candidate amp scripts still contain the article's
50/100/2000 definition. Existing local deletion samples contain yet another
historical set, 50x40, 100x40, 500x40. Training discovers shapes from the first
sample at runtime, so the generated files—not the mutation name—ultimately decide
the model's branch input sizes.


2. END-TO-END FLOW
------------------

Common starting point
  Data/merged_dataframe/merged_dataframe_<CANCER>.tsv
    -> per-chromosome bin matrices
    -> reduce/pad patient columns to a fixed width (normally 40)
    -> select positive and negative center bins from mutation-specific YAML
    -> extract three centered genomic windows
    -> write one labeled TSV per center
    -> TSVDataset parses the three matrices
    -> shared CNN branches + cross-branch attention + binary classifier
    -> cross-validation, metrics, checkpoints, inference/mapping

amp route
  merged CNA data
    -> focal/arm filtering and general CN binning
    -> bin_with_case_amp_compressed (or experiment-specific variants)
    -> gen_dataset/config.yaml + type_centers_index*.yaml
    -> gen_dataset/gen_sample_amp.py (or an older experiment generator)
    -> GeneratedSamples_amp_...
    -> shared training/model code
    -> experimental/amp/...

del route
  merged CNA data
    -> preprocess/Version0209/gen_bin_del.cpp
       (CN < 2 only; diploid baseline 2)
    -> bin_with_case_del -> bin_with_case_del_compressed[_40/_80]
    -> gen_dataset/config_del.yaml + type_centers_del.yaml
    -> gen_dataset/gen_sample_del.py (or gen_sample_del_old.py)
    -> GeneratedSamples_del_...
    -> shared training/model code
    -> experimental/del/...

4. STAGE-BY-STAGE INTERPRETATION
--------------------------------

4.1 Raw CNA representation and bin construction

The deletion split happens early and intentionally. In
preprocess/Version0209/gen_bin_del.cpp, only CN<2 segment endpoints are used to
create bins. All patients are initialized to 2 in every deletion bin, and a
covering deletion lowers that patient's value by its distance below 2. This makes
normal positions bright/constant at 2 and deletions downward deviations.

The inspected amplification-side bin builder,
preprocess/Version0209/gen_bin_0306_cpp.cpp, instead filters arm-level records,
uses every retained segment endpoint, and sums raw Copy_Number for every covering
segment. It therefore retains a fuller focal copy-number landscape rather than
creating an amp-only 2-versus->2 matrix. “amp” is ultimately defined by the
labeled center and learned peak pattern, not by a CN>2 filter in that builder.

This is the most important semantic difference. It means del and amp matrices
are not simple sign-flipped copies and cannot safely share center indices or
trained checkpoints.

4.2 Standardizing the patient/sample axis

The article says cohorts are normalized to 40 channels: cohorts with more than
40 samples are folded by modulo assignment and averaged; cohorts with fewer than
40 are padded with diploid value 2.

preprocess/compress.py uses a related but more selective implementation for both
types. It first ranks patient columns by whole-matrix mean and keeps the top 40 as
anchors, then assigns all remaining columns to those anchors round-robin and
averages. Below 40, it pads with 2. Because the same descending-mean rule is used
for deletion matrices, its semantic effect differs: high means in del data tend
to identify relatively normal/less-deleted samples, whereas high means in amp
data tend to identify higher-copy samples. This is a behavior difference caused
by the data representation, even though the code is shared.

There is also a schema detail: compress.py treats the final column as a suffix
and excludes it from patient compression. This matches amp's explicit `sum`
column. The deletion bin format shown by gen_bin_del.cpp has no explicit suffix;
therefore understanding any particular del dataset requires checking which
preprocessor/version created it rather than assuming the schemas are identical.

4.3 Labeled center selection

Both generators consume manually/tool-curated positive and negative centers and
write label 1 or 0 respectively. The article says positives combine visual
curation with GISTIC2 and RUBIC results; centers found by both tools, or unique to
one tool but visually confirmed, may be included. This labeling principle is the
same for amp and del, but the actual YAML center lists are different and are
indexed against different bin grids. The deletion-only endpoints change its row
coordinate system, so an amp row index generally does not denote the same genomic
location in del.

4.4 Multi-scale sampling

For each labeled bin, both pipelines extract three symmetric genomic contexts.
Every matrix has 40 patient columns, but amp uses much taller contexts because
the empirical amplification-length distribution motivated broader windows. del
uses 20/50/400 in the article and current YAML. The three matrices remain separate
branches rather than being resized to a single common height.

Important version distinction:

* Article and stable older amp scripts: 50/100/2000.
* Current gen_dataset/config.yaml: 50/250/2000.
* Article and current gen_dataset/config_del.yaml: 20/50/400.
* Existing GeneratedSamples_del_compressed files: 50/100/500, matching
  gen_dataset/gen_sample_del_old.py rather than current config_del.yaml.

This is configuration/history drift, not a del/amp model-architecture difference.
For reproducibility, a run should be described by both mutation type and exact
sample directory/generator configuration.

4.5 Neural network and training

Model/Models.py creates one structurally identical branch for every matrix found
in the input sample. Each branch applies separable convolution, batch norm, ReLU,
max pooling, three residual blocks, ECA channel attention, adaptive average
pooling and a linear projection. The three feature vectors are stacked; 4-head
self-attention models cross-scale interactions; a residual FFN refines them;
branch-wise mean pooling and an MLP produce one logit.

No conditional `if mut == amp/del` exists inside this model. Different window
heights affect computation and receptive context, but adaptive pooling makes the
same architecture accept either shape family. Likewise, the inspected training
functions use the same loss and hyperparameters. Separate checkpoints are needed
because the input distributions and learned tasks differ, not because two model
classes are defined.

Two evaluation organizations coexist:

* Model/auto_cross_ct_val.py implements leave-one-cancer-project-out evaluation:
  one cancer type is validation and all others train. This matches the article's
  primary TCGA evaluation description. Its amp and del branches only select
  different sample directories.
* Model/theta.py (amp) and Model/kFold_panCancer.py (del) implement ordinary
  stratified 5-fold evaluation over the combined samples. These two files are
  otherwise identical in the inspected checkout. This is a later/alternative
  experiment design and should not be confused with article LOO results.


5. WHAT IS TRULY SHARED VS. MUTATION-SPECIFIC
----------------------------------------------

Mutation-specific:

* Biological event filtering and numerical meaning of the chromosome matrix.
* Bin boundary grid and thus center row indices.
* Center-label YAML files.
* Multi-scale window heights.
* Input sample directories, model checkpoint directories, and mapped outputs.
* In this checkout, some preprocessing schema/extension conventions.

Shared:

* Fixed width of 40 patient channels.
* General centered-window extraction, boundary rolling, column sorting/fitting,
  sample TSV serialization, and labels 1/0.
* TSVDataset parsing and batch collation.
* CNN/residual/ECA branch design, multi-head cross-scale attention, FFN, mean
  fusion, and MLP classifier.
* BCE-with-logits objective, Adam optimization, adaptive LR schedule, metrics,
  F1-based checkpoint selection, ROC output, and most experiment logging.


6. PAPER-TO-CODE ALIGNMENT
--------------------------

Strong alignments:

* Separate amplification and deletion learning tasks.
* Deletion processing ignores copy gains and uses deviation from diploid 2.
* Three mutation-specific genomic scales, each with 40 patient channels.
* Use of real neighboring matrix content instead of constant boundary padding.
* Parallel feature branches, residual feature learning, cross-scale attention,
  binary classification with BCEWithLogitsLoss.
* A leave-one-project-out training/evaluation implementation exists.

Implementation/version differences to keep in mind (not a bug inventory):

* Current amp YAML's middle window is 250 rather than the article's 100.
* Existing local del sample artifacts use 50/100/500 rather than current
  20/50/400.
* Current k-fold scripts are not the article's LOO protocol.
* The checked-in 40-column compression ranks anchor columns before modulo folding,
  while the article describes modulo folding/averaging more generally.
* The amp focal bin builder removes arm-level records, while the article presents
  CRESCENT as detecting both focal and broad events. Other experiment-specific
  preprocessing files may have been used for broad-event analyses.
* The repository contains many legacy and experiment variants. Directory names
  such as `_80`, `_40`, `XR_late_norm`, `baseline_improved`, and old generators
  are meaningful provenance, not interchangeable aliases.


7. PRACTICAL READING GUIDE
--------------------------

For the clearest understanding of the current design, read in this order:

1. preprocess/Version0209/gen_bin_del.cpp
   Definitive explanation of why and how deletion matrices differ.

2. preprocess/Version0209/gen_bin_0306_cpp.cpp
   General/focal binning path used as the amplification-side comparison.

3. preprocess/compress.py
   Shared 40-column reduction with mutation-specific directories.

   Current amp/del data roots, extensions, and scale definitions.

5. gen_dataset/gen_sample_amp.py and gen_dataset/gen_sample_del.py
   Label resolution, normalization, window extraction and serialization.

   Shared parsing and model architecture.

   Article-like leave-one-project-out experiment path.

8. Model/theta.py and Model/kFold_panCancer.py
   Later amp and del stratified k-fold entry points.

9. Model/check.py and Model/mapping.py
   Mutation-specific inference directories and mapping back to genome bins.

9. BOTTOM LINE
--------------

Think of this project as two different data encoders feeding one classifier:

  amp encoder = broader raw-copy-number contexts around amp-labeled centers
  del encoder = smaller deletion-isolated contexts around del-labeled centers
  shared learner = three CNN branches + cross-scale attention + binary head

The `mut_type` string itself is not what teaches the network amplification versus
deletion. The distinction is already embedded in the chromosome matrices, center
annotations, window sizes, chosen sample directory, and separately trained
checkpoint. Consequently, the most reliable way to reproduce or compare the two
pipelines is to record the exact preprocessing executable, YAML files, generated
sample directory and observed scale headers alongside the mutation type.
